# Legal-v1 runner — Phase 4A (fake only)

`python3 tools/run_legal_benchmark.py --dry-run --fake-agent --condition ALL --run-id <unique-safe-id>` stages one allowlisted workspace per condition/case. `--condition EAGER` selects a single condition. A run ID may not be reused. Fake artifacts (including workspaces) go **only** to ignored `.pi-cache/legal-runner-dry-runs/<run-id>/`. The optional `--output-root` must exactly equal the canonical root for the selected mode; invalid requests fail rather than redirect. Tests clean up their scratch runs. `results/raw/legal-v1/<run-id>/` is reserved for a separately authorized future live run; this program has no live adapter or path that writes there. `--live`, including `--live --authorize-live`, is blocked with `LIVE_BLOCKED_NETWORK_ISOLATION_UNVERIFIED` before any agent process starts.

## Installed agent interface (local inspection only)

`/Users/antonv/.pi/agent/bin/pi` (`pi --help`, installed 0.87.1 documentation) supports `--mode json` noninteractive event streaming and long-lived `--mode rpc` with a `prompt` command and `agent_settled` completion event. A single RPC session can receive t1 then t2, while separate case processes/sessions can be fresh. `--provider`, `--model`, and `--thinking` select runtime settings; the *experimental* model remains unapproved. Pi has `--tools`/`--no-tools`, `--no-context-files`, `--no-extensions`, and `--no-skills`; cwd is the subprocess cwd, not a verified confinement boundary. JSON events include tool call starts/ends, authoritative completed messages, and provider-reported usage when available. If exact usage is absent, record `UNAVAILABLE`, not an estimate. The ordinary read/bash tools do not guarantee per-file byte counts or reliable denied-path/network event logging. A future live adapter must use audited wrappers, not model self-report alone. Pi's `--offline` disables **startup** network operations, not provider/tool networking. No prompt was sent during interface inspection.

`/usr/bin/sandbox-exec` exists on this macOS host, but no complete tested OS-level policy currently confines BOTH filesystem access to the staged workspace and all network egress (including GitHub). Pi's tool allowlists and a staged cwd alone do not isolate a process from parent paths or the network; an unrestricted bash tool can bypass Python read guards. Docker was discovered but no container or policy was installed/verified. Therefore live remains blocked even with an authorization flag. A future adapter must prove network/GitHub denial, repo-root denial, credential isolation, auditable tool events, and model/provider/reasoning attestation before owner authorization; never launch it from the repository root. No experimental agent subprocess is started in Phase 4A.

## Fake execution and boundaries

The runner validates frozen hashes/conditions/corpus and canonical evaluator gold privately before staging. It extracts **only** the lookup classification evaluator-side for forced control; it never stages gold, answer criteria, expected sections, or the category. EAGER initial disclosure is the complete checked-in legal skill plus a map of citations/headings (no statutory section text); PROGRESSIVE and FORCED share byte-identical capability name/description only. The complete skill is present as a staged file but is read only when the fake adapter selects it. For REQUIRED and CHECK_REQUIRED_TO_ESTABLISH_LIMITATION, FORCED adds only `Consult the pinned Title 17 corpus before answering this turn.` NOT_NEEDED receives no control; REUSE_OR_TARGETED may reuse prior source or choose targeted retrieval. Fake tool events are simulated and explicitly labeled `fake`; **no** frozen prompt is sent to the real lexical tool. Real source and search files are staged but never used for retrieval by the fake agent.

The fake agent has a fresh object/session per case and retains the actual generated t1 response in its history before t2 in the same session. It returns deterministic placeholder text, not an answer or score. Turn rows capture timestamps, fixed fake wall time, initial-disclosure bytes/hash, event counts, file events, null provider/model/reasoning, null actual tokens with `token_usage_status: UNAVAILABLE`, and separately labeled fixed fake token counts. Case rows aggregate turn counts/events. Exact citation/search calls, queries, returned IDs, read bytes, opened sections, denied attempts, errors, and network denials are *future instrumentation fields*: not fabricated as observations from the fake adapter. All data is engineering scratch, never a benchmark result.

Scratch files: `run-manifest.json`, `environment-attestation.json`, `initial-disclosures.json`, `workspace-manifests.jsonl`, `per-turn.jsonl`, `per-case.jsonl`, `session-events.jsonl`, `stdio.json`, `COMPLETED.json`, and `workspaces/`. The manifest declares `execution_kind: FAKE_DRY_RUN`, `model_execution_authorized: false`, `live_model_invoked: false`, `benchmark_scoring_performed: false`, and `canonical_result_artifact: false`. The checked-in run config pins benchmark/corpus/condition hashes but leaves provider, model, reasoning, and temperature unapproved; Pi's coding model is **not** the approved experimental model. Execution order is EAGER, PROGRESSIVE, FORCED_RETRIEVAL_CONTROL, with frozen case order within each. One attempt only; no semantic or automatic retries; infrastructure failures are not silently replaced. Execution does not score against gold.

A future live adapter must additionally attest clean tracked HEAD, origin/main or an explicitly pinned allowed commit, runner commit, corpus and question hashes, condition SHA, provider/model/reasoning, evaluator-side gold commitment, and verified workspace and OS isolation. Fail closed on any mismatch. Future raw outputs under `results/raw/legal-v1/` require separate owner-approved execution authorization and a new verified adapter. Never mutate frozen legal-v1 to make an implementation pass.
